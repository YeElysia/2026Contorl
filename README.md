# 2026Contorl

STM32H750VB 智能搬运机器人比赛控制工程，使用 Arduino Framework
和 PlatformIO。项目不依赖 OPS9，以底盘步进脉冲、JY901 航向、
MaixPro 视觉和分层非阻塞状态机完成比赛流程。

## 当前模块

| 模块 | 目录 | 职责 |
|---|---|---|
| 底盘控制 | `lib/ChassisControl` | 麦轮逆解算、统一运动接口、世界位姿和IMU航向 |
| 路线执行 | `lib/MissionControl/RouteExecutor.*` | 顺序执行快速/精确移动和绝对旋转 |
| 比赛状态机 | `lib/MissionControl/MissionController.*` | 编排扫码、移动、对准和机构任务 |
| 二维码 | `lib/QRCodeMissionProvider` | 解析 `134+123+314+231` 格式任务码 |
| MaixPro | `lib/MaixProVision` | V2协议、原料颜色识别和工位闭环对准 |
| 机械臂 | `lib/MechanismControl` | 非阻塞取料、粗加工放取和暂存码垛 |
| 串口屏 | `lib/MissionDisplay` | 显示任务状态、故障和换行任务码 |

供应商库保留在 `lib/TTL_STEPPER`、`lib/AccelStepper-master`、
`lib/fashionstar-*` 等目录，自研业务逻辑不直接修改这些库。

## 配置入口

- `include/chassis_config.h`：底盘引脚、机械尺寸、速度和航向控制。
- `include/mechanism_config.h`：机械臂 ID、引脚、速度和全部实车点位。
- `include/mission_config.h`：按键、状态灯、扫码器和串口屏。
- `include/vision_config.h`：MaixPro 引脚、目标中心、闭环增益和软限位。
- `lib/MissionControl/MissionRoutes.h`：各比赛区域之间的底盘路线。

实车标定只修改配置文件，不在状态机或动作执行器中散落常量。

底盘只创建一个全局`ChassisControl`实例。路线、视觉微调和机构
协同均通过该实例的受限接口调用，不直接访问四个移动电机。默认
世界坐标记录底盘几何中心，出发位姿为`(185, 150, 0°)`；
X轴正向指向初始车体左侧、Y轴正向指向初始车头。x/y根据
四轮实际步数积分，r使用JY901反馈。底盘宽230 mm、长300 mm。
比赛主路线使用世界绝对坐标点，视觉对准继续使用车体相对坐标。
每个工位任务结束后，底盘先以精确档恢复该区域的`x/y`基准，
再执行固定的避障点和长距离转场，防止视觉微调误差传到下一站。
航向由IMU保持，所有`r`改变均在场地中心`(1200, 1200)`执行。
原料区和粗加工区固定点位于`x=1200`轴线，暂存区固定点位于
`y=1200`轴线；各区域最后50 mm使用精确档停靠。

## 主要硬件映射

| 设备 | 接口 |
|---|---|
| JY901 | PD9 RX / PD8 TX，115200 |
| GM75 | PE0 RX / PE1 TX，9600 |
| 串口屏 | PB15 RX / PB14 TX，115200 |
| MaixPro | PE7 RX / PE8 TX，115200 |
| 升降、伸缩步进 | PA3 RX / PA2 TX，ID 7 / ID 6 |
| 底座步进 | PA10 RX / PA9 TX，ID 5 |
| 夹爪、载物盘舵机 | PC7 RX / PC6 TX，ID 4 / ID 5 |
| 一键启动 | PB9 |
| 状态灯 | PA15 |

PB12/PB13 为独立启动诊断串口，波特率115200。PB13只输出
低频ASCII文本，不复用IMU、屏幕或机构总线，避免出现二进制乱码。
其中 `storage=目标角/实测角/协议状态/有效反馈数/查询数`，
`gripper` 字段格式相同；协议状态0为成功、8为响应超时。
原料对准时还会输出
`grasp=物料序号/找到/dx/dy/质量/底盘偏移/伸缩目标/状态`，
用于判断像素标定方向和是否触及视觉软限位。
工位对准输出
`align=状态/模式/目标/找到/dx/dy/质量/稳定帧/运动状态`；
模式`EE`表示圆环识别，`CC`表示复用原料颜色识别。

## 第一阶段任务流程

```text
上电初始化
→ 等待一键启动
→ 前往二维码区并读取任务码
→ 第一批：原料区取料 → 粗加工区放置并取回 → 暂存区平放
→ 第二批：原料区取料 → 粗加工区放置并取回 → 暂存区同色码垛
→ 返回启停区
```

原料抓取按照任务码颜色逐个执行：

```text
机械臂到抓取准备位
→ MaixPro 跟踪目标颜色
→ 底盘只做前后微调，朝转盘方向由伸缩轴补偿
→ 连续稳定后下降夹取
→ 物料放入车载盘
```

三个物料全部装车后，底盘先自动返回原料区到站基准，再执行
下一段固定路线。原料区抓取接口不提供左右横移能力，避免车辆
向右靠近转盘或把视觉修正误差传递到后续路线。

首次发车时机械臂保持上电初始化位。底盘到达扫码区后，二维码
读取与机械臂切换到运输收纳位同时进行；两者都完成后才前往原料区。

暂存区每轮使用不同的视觉参考：

```text
第一轮到站
→ 机械臂进入视觉姿态（lift=900）
→ 识别2号圆环并完成整车对准
→ 按第一批任务码位置平放三个物料

第二轮到站
→ 从任务码计算第一轮2号位的物料颜色
→ 复用原料颜色识别，对准该颜色物料
→ 第二批每个物料放到第一批同色位置并码垛
```

扫码后状态机会再次校验两批颜色集合和同色位置映射。若第二批颜色
无法在第一批中找到，或者码垛位置与第一批同色物料位置不一致，
任务会在离开扫码区前进入故障，不执行错误码垛。

工位最后一个物料放稳并抬升到安全高度后，底盘立即驶向下一
区域。机械臂底座、伸缩轴和载物盘在行驶期间异步回到运输收纳位；
如果底盘先到达，状态机会等待机构收纳完成后再启动下一工位动作。

机械臂内部使用并行动作组：底座旋转、升降抬升、伸缩回收、夹爪
动作和载物盘旋转会按动作表执行，其中升降轴始终独占动作组，
不会与任何其他执行器并行。下降抓取、夹紧物料以及长臂伸出保留
顺序屏障，避免未夹稳或底座方向不正确时提前伸出。

## 启停区选择

发车前读取串口屏 `DEBUG.n4.val`：

- `0`：右下启停区，初始底盘中心坐标 `(185, 150)`；
- `1`：右上启停区，初始底盘中心坐标 `(185, 2250)`。

按下实体启动键时锁定选择值并重置底盘世界坐标。任务结束后，
状态机会沿右侧中心线返回同一个启停区。调试输出中的 `zone=0/1`
可用于确认本次任务采用的启停区。

## 构建

```sh
pio run
pio run -t upload
```

首次运行或修改机械臂点位后，应架空底盘并清空机构周围空间，
确认初始化方向、软限位和紧急停车行为后再落地测试。

## 机械臂独立测试

`mechanism_test`环境不会初始化底盘、JY901、扫码器、串口屏和
MaixPro，适合把机械臂模块单独放在工作台测试：

```sh
pio run -e mechanism_test
pio run -e mechanism_test -t upload
```

上电初始化完成后，PA15状态灯熄灭。每按一次PB9依次执行：

1. 上电初始位转到运输收纳位；
2. 原料区三个物料抓取流程（视觉目标由测试程序模拟为居中）；
3. 粗加工区三个物料的放置和取回；
4. 暂存区三个物料的最终放置。

每个工位测试完成后会自动执行一次运输收纳。状态灯慢闪表示
初始化、常亮表示动作运行、快闪表示故障；执行下一项前应根据
任务需要摆好测试物料，并确保机构运动范围内无人和障碍物。

## 圆环对齐独立测试

`ring_alignment_test`环境只运行粗加工区圆环视觉对齐流程，便于
单独核对相机坐标方向、像素到毫米增益和底盘运动方向：

```sh
pio run -e ring_alignment_test
pio run -e ring_alignment_test -t upload
```

将小车放在粗加工区圆环附近，上电并等待机构初始化完成。单击
PB9后，机械臂先进入粗加工区识别姿态并将升降轴降到900，随后
MaixPro开始识别圆环并驱动底盘对齐。测试程序采用当前约定：
相机报告`dx > 0`时底盘向后修正，报告`dy > 0`时底盘向左修正，
使两个图像误差逐步回到零。

PB13调试串口使用115200波特率，每500毫秒输出一次`RING`日志。
其中`dx/dy`是相机误差，`moveF/moveR`是本轮计划的前进和右移
距离，`stable`是连续进入容差范围的帧数。状态灯慢闪表示等待或
对齐中，常亮表示对齐完成，快闪表示故障。首次实车测试应确保
底盘四周有足够移动空间，并随时准备断电。
