# 底盘漂移到位纯逻辑

本文只描述底盘“漂移到位”的数学模型、控制流程和边界，不包含具体路线配置、机械参数标定或硬件驱动细节。

## 1. 坐标系

系统使用固定世界坐标系：

- `+x`：机器人初始位置的左侧。
- `+y`：机器人初始车头方向。
- `yaw = 0°`：车头指向世界 `+y`。
- 位置单位为毫米，角度单位为度。
- 车体坐标中，`forward > 0` 表示向车头，`right > 0` 表示向车体右侧。

底盘持续维护估计位姿：

```text
Pose = (worldX, worldY, worldYaw)
```

世界位移和车体位移之间通过当前航向转换。航向为 `yaw` 时：

```text
worldX = -forward * sin(yaw) + right * cos(yaw)
worldY =  forward * cos(yaw) + right * sin(yaw)
```

反变换用于将世界坐标速度转换为车体前进和右移速度。

## 2. 漂移的定义

这里的“漂移”不是依靠不可控打滑改变运动方向，而是同时控制三个量：

1. 麦轮平移速度；
2. 车体绕垂直轴的旋转速度；
3. 位置和航向的闭环误差。

因此机器人可以一边沿路径前进，一边改变车头方向，最后以目标位置和目标航向结束。

漂移入口是：

```text
moveWorldToPose(targetX, targetY, targetYaw, maxRpm, acceleration)
```

普通 `moveWorldTo()` 只要求到达位置并保持当前航向；`moveWorldToPose()` 还会在运动过程中完成目标航向变化。

## 3. 目标轴选择

开始漂移时，先计算当前位置到目标位置的世界位移：

```text
Δx = targetX - currentX
Δy = targetY - currentY
```

控制器根据起步时的车体航向，选择最接近目标位移方向的车体轴：

- 车头方向；
- 车尾方向；
- 车体右侧；
- 车体左侧。

选择结果决定初始路径方向。这样可以让漂移开始阶段尽量使用纯前后或纯左右运动，减少起步时的横向误差和轮速突变。

路径方向定义为：

```text
path = (directionX, directionY)
```

路径长度为：

```text
length = sqrt(Δx² + Δy²)
```

## 4. 误差分解

控制周期内，将当前估计位置相对路径起点的误差分解为沿程误差和横向误差。

设：

```text
positionError = currentPosition - pathStart
```

则：

```text
along = dot(positionError, path)
cross = cross(path, positionError)
```

其中：

- `along` 表示沿路径方向已经走过的距离；
- `cross` 表示偏离理想直线的距离；
- 终点剩余距离约为 `length - along`。

控制器分别处理这两个误差：

- 沿程方向由 jerk 限制的 S 曲线给出参考速度；
- 横向方向由比例修正产生横移速度；
- 最终将世界坐标速度转换为车体速度，再进行麦轮逆解。

## 5. 动态转向窗口

漂移不会从起点立刻旋转。控制器根据目标航向差、路径速度和旋转安全余量估算转向窗口：

```text
headingError = wrap180(targetYaw - currentYaw)
```

窗口表示“距离终点还剩多少时开始转向”。它受到以下限制：

- 不能超过当前路径长度；
- 不能小于配置的保守最小窗口；
- 路径太短时不能强行高速完成大角度旋转；
- 必须为旋转减速和 IMU 延迟留出余量。

当剩余路径距离进入窗口：

```text
remaining <= turnWindow
```

控制器将 `_trackTurnStarted` 置为真，并开始执行目标航向控制。

窗口前，车体保持起步航向；窗口内，平移和旋转同时进行。

## 6. 航向控制

航向误差先归一化到 `[-180°, 180°)`，避免跨越 `±180°` 时选择长方向旋转。

旋转速度由剩余角度决定：

1. 大角度时使用平方根减速曲线，保证接近目标时逐步降低速度；
2. 小角度时使用线性末端曲线，降低过冲和震荡；
3. 进入航向容差后，目标旋转速度为零；
4. 旋转命令还受到旋转加速度斜坡限制。

小角度区域使用更低的最低旋转速度，避免控制器在已经接近目标时仍以过高速度推动车体。

## 7. 航向门控

当车体正在旋转时，平移不能无条件继续跑完，否则可能出现“位置先到、航向还没到”的情况。

控制器根据航向完成比例限制可使用的剩余平移距离。核心逻辑可表示为：

```text
headingRatio = completedHeading / totalHeading
allowedRemaining = remainingDistance * headingRatio
```

当航向尚未开始旋转或目标航向已经达到时，不进行额外限制。目标航向差越大、实际旋转进度越小时，允许的平移进度越保守。

这保证了：

- 平移不会明显领先于旋转；
- 旋转延迟时，路径速度会自动受到限制；
- 目标位置附近仍保留足够距离完成航向调整。

航向门控函数还处理以下边界：

- 零航向差；
- 零转向窗口；
- 负剩余距离；
- 已经越过目标点；
- 旋转方向变化。

## 8. Jerk 限制的平移轨迹

平移参考不是直接把速度切换到最大值，而是维护：

```text
JerkState = {
    position,
    velocity,
    acceleration
}
```

每个控制周期执行积分：

```text
acceleration += jerk * dt
velocity     += acceleration * dt
position     += velocity * dt
```

其中 jerk 是加速度变化率。

`jerkStep()` 会在候选 jerk 中选择当前最合适的值，同时满足：

- 加速度不超过上限；
- 速度不低于零；
- 速度不超过最大速度；
- 到达目标前可以刹停；
- 不能因为单个控制周期越过目标而产生明显反向运动。

因此平移过程具有：

```text
加加速 -> 加速 -> 匀速 -> 减速 -> 平滑停车
```

实际控制速度还会加入沿程位置误差修正，使里程计实际位置跟随 S 曲线参考位置，而不是只依赖开环时间。

## 9. 横向误差修正

理想路径只提供沿程方向，但实际车体会受到轮胎摩擦、地面不平和负载变化影响而产生横向误差。

横向修正速度近似为：

```text
crossVelocity = crossKp * crossError
```

修正量会被限制在路径速度的一定比例内，避免横向修正抢占全部轮速，也避免误差瞬间放大造成轮速突变。

漂移过程中，目标横向偏差只在转向窗口内逐渐并入。这样可以保持起步阶段的简单直线路径，并在后段将车体平移到最终目标点。

## 10. 位姿稳定阶段

航向第一次进入容差时，不立即认为漂移完成。控制器进入：

```text
PoseHeadingSettling
```

稳定阶段执行以下步骤：

1. 暂停平移和旋转输出；
2. 输出零速度，等待电机和车体惯性消失；
3. 等待新的 IMU 样本；
4. 连续检查航向仍在容差范围内；
5. 同时满足稳定样本数和最短稳定时间后，确认航向完成。

如果稳定期间航向重新离开容差：

- 清除稳定计数；
- 恢复旋转控制；
- 不把本次短暂进入容差视为完成。

这样可以避免 IMU 单帧噪声或车体惯性导致提前结束。

## 11. IMU 与脉冲航向预测

IMU数据存在采样周期和串口传输延迟。为了减少两帧 IMU 之间的控制滞后，当前航向估计同时使用：

- 最近一次有效 IMU 航向；
- 最近 IMU 帧之后累计的旋转电机脉冲。

在两次 IMU 帧之间，控制器根据旋转脉冲和标定的旋转脉冲比例外推当前航向：

```text
predictedYaw = imuYaw + pulseRotationDelta
```

收到新的 IMU 帧后重新对齐基准。IMU长时间没有更新时，仍会触发航向数据过期保护，不能无限依赖外推值。

## 12. 麦轮速度合成

控制器最终得到三个车体速度量：

```text
forwardVelocity
rightVelocity
rotationVelocity
```

麦轮逆解将其合成为四个轮子的速度命令。抽象形式为：

```text
front-left  = forward + right + rotation
front-right = forward - right + rotation
rear-left   = forward - right + rotation
rear-right  = forward + right + rotation
```

随后应用：

1. 每个电机的方向符号；
2. 毫米/秒到步进脉冲/秒的换算；
3. 最大步进频率限制；
4. 速度模式看门狗刷新。

如果合成后的某个轮速超过硬件上限，系统进行最终等比例缩放，保证任何单轮都不会超出最大脉冲频率。

## 13. 普通平移、漂移和连续途经点的区别

### 普通世界坐标平移

```text
moveWorldTo(x, y, ...)
```

- 沿当前目标点直线移动；
- 保持既定航向；
- 到达后可执行最终航向静定。

### 漂移到位

```text
moveWorldToPose(x, y, yaw, ...)
```

- 沿目标位移方向起步；
- 在终点前的动态窗口内开始旋转；
- 平移进度受航向进度门控；
- 同时修正沿程、横向和航向误差；
- 最后进入位姿稳定阶段。

### 连续途经点

```text
moveWorldThrough(viaX, viaY, targetX, targetY, ...)
```

- 将途经点作为路径转换位置，而不是停车点；
- 第一段接近途经点时提前启动第二段；
- 第一段尚未完成的参考速度会投影到第二段方向；
- 两段参考轨迹叠加，形成连续过弯；
- 最终目标点仍然需要完成正常减速和停车。

`MoveThrough` 与 `MoveToPose` 的区别是：前者解决路径段之间的连续性，后者解决单段运动中的位置与航向同时变化。

## 14. 当前边界和安全条件

当前控制逻辑不是通用路径规划器，也没有自动障碍物地图。它不能仅凭数学控制保证任意路线安全。

使用漂移前必须确认：

- 目标路径和转向窗口内没有障碍物；
- 车体外廓和麦轮扫掠区域均有足够余量；
- 旋转过程中机构、料盘和机械臂不会碰撞场地设施；
- 目标点附近有足够空间完成最终稳定；
- IMU、里程计和电机方向已经完成标定；
- 路线点位经过实车验证，而不是只通过坐标几何验证。

特别是连续途经点的圆滑拐弯，会使车体轨迹偏离两个点之间的折线。拐角内侧必须按实际车体扫掠范围留出余量。

## 15. 纯逻辑验证

纯数学测试应至少覆盖：

- jerk 积分结果；
- 不同控制周期下的 jerk 轨迹；
- 速度、加速度和位置边界；
- 航向门控的零角度、半角度、完成和反向情况；
- 路径沿程误差和横向误差；
- 目标点已经越过的情况。

当前 host-side 数学测试输出：

```text
chassis_tracking_host_test: PASS
```

纯逻辑测试不能替代实车验证。实车还需要重点观察：

- 小角度旋转是否过冲；
- 漂移开始和结束时是否有明显轮速突变；
- 横向误差是否收敛；
- IMU丢帧时是否正确进入故障或保护状态；
- 连续途经点是否确实不停车；
- 转向窗口内的车体扫掠是否满足场地安全余量。
